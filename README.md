# Wishlists

Wishlist service for NYU CSCI-GA.2820-003, DevOps and Agile Methodologies. Customers can create named wishlists to keep track of products they want to buy.

Built with Flask, SQLAlchemy, and PostgreSQL.

## Local Setup

You will need Git, Docker Desktop, and VS Code with the Dev Containers extension.

1. Start Docker Desktop.
2. Clone the repository:

```bash
   git clone https://github.com/CSCI-GA-2820-FA26-003/wishlists.git
   cd wishlists
```

3. Open the `wishlists` folder in VS Code.
4. Open the Command Palette and select **Dev Containers: Reopen in Container**.
5. Wait for the container setup to finish, then open a terminal in VS Code.

The setup installs the Python dependencies and starts PostgreSQL in a separate container. Run the commands below in the development container's terminal, from `/app`.

## Running the Service

```bash
honcho start
```

Open <http://localhost:8080/>. The root URL returns the service name, version, and the path of the wishlist collection. If VS Code forwards a different local port, use the address in the Ports tab. Stop the server with `Ctrl+C`.

## Tests and Code Checks

Run all tests:

```bash
make test
```

Tests must pass with at least 95% coverage. They clear Wishlist and Item records in the configured database, so only run them against a development or test database.

Run the code checks:

```bash
make lint
```

This runs Flake8 and Pylint. Check the output for errors and warnings, even if the command finishes.

## API

Every response with a body is JSON; successful `DELETE` requests return `204 No Content` with an empty body. `POST` and `PUT` requests must send `Content-Type: application/json`.

| Method | Path | Purpose | Success |
| --- | --- | --- | --- |
| GET | `/` | Service information | `200 OK` |
| GET | `/wishlists` | List wishlists, optionally filtered by `customer_id` or `name` | `200 OK` |
| POST | `/wishlists` | Create a wishlist | `201 Created` + `Location` header |
| GET | `/wishlists/{id}` | Read one wishlist with its items | `200 OK` |
| PUT | `/wishlists/{id}` | Update a wishlist's name and customer | `200 OK` |
| DELETE | `/wishlists/{id}` | Delete a wishlist and its items | `204 No Content` |
| POST | `/wishlists/{id}/items` | Add an item | `201 Created` + `Location` header |
| GET | `/wishlists/{id}/items/{item_id}` | Read an item | `200 OK` |
| GET | `/wishlists/{id}/items` | List items in a wishlist | `200 OK` |
| PUT | `/wishlists/{id}/items/{item_id}` | Update an item | `200 OK` |
| DELETE | `/wishlists/{id}/items/{item_id}` | Delete an item | `204 No Content` |

### Wishlist JSON

```json
{
  "customer_id": 123,
  "id": 7,
  "items": [
    {"id": 1, "note": "red one", "product_id": 456, "purchased": false, "wishlist_id": 7}
  ],
  "name": "Birthday"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `id` | Integer | Generated by the database. Never read from a request body. |
| `name` | String | Required. At most 63 characters. Cannot be empty or contain only whitespace. |
| `customer_id` | Integer | Required. Identifies the customer. A customer can have several wishlists, including ones with the same name. |
| `items` | Array | Items in the wishlist. Each item has an `id`, `wishlist_id`, `product_id`, an optional `note` and a `purchased` flag. Add items through the item endpoint after creating the wishlist. |

### GET /

Returns `{"list_url": "/wishlists", "name": "Wishlists Service", "version": "1.0.0"}`.

### GET /wishlists

Returns a JSON array of wishlists, each in the format above. Returns `[]` when there are none.

Optional query parameters:

- `customer_id` (integer): only wishlists owned by that customer.
- `name` (exact match): only wishlists with that name.

If both are given, `customer_id` is used and `name` is ignored. A query with no match returns `200 OK` with `[]`.

```bash
curl -i http://localhost:8080/wishlists
curl -i "http://localhost:8080/wishlists?customer_id=1"
curl -i "http://localhost:8080/wishlists?name=Birthday"
```

- `400 Bad Request`: `customer_id` is not an integer.

### POST /wishlists

Creates an empty wishlist. The body needs `name` and `customer_id`. `items` may be omitted or sent as `[]`.

```bash
curl -i -X POST http://localhost:8080/wishlists \
  -H 'Content-Type: application/json' \
  -d '{"name": "Birthday", "customer_id": 123}'
```

Returns `201 Created` with the new wishlist in the body and a `Location` header pointing to it, for example `http://localhost:8080/wishlists/7`.

- `400 Bad Request`: missing or invalid `name` or `customer_id` (including a `name` longer than 63 characters), or a non-empty `items` list.
- `415 Unsupported Media Type`: the request is not JSON.

### GET /wishlists/{id}

```bash
curl -i http://localhost:8080/wishlists/7
```

Returns `200 OK` with the wishlist and its items.

- `404 Not Found`: no wishlist with that id.

### PUT /wishlists/{id}

Updates `name` and `customer_id`. An `id` or `items` in the body is ignored; items are managed through their own endpoints.

```bash
curl -i -X PUT http://localhost:8080/wishlists/7 \
  -H 'Content-Type: application/json' \
  -d '{"name": "2026 Birthday Wishlist", "customer_id": 123}'
```

Returns `200 OK` with the updated wishlist.

- `400 Bad Request`: missing or invalid `name` or `customer_id` (including a `name` longer than 63 characters), or a body that is not a JSON object.
- `404 Not Found`: no wishlist with that id.
- `415 Unsupported Media Type`: the request is not JSON.

### DELETE /wishlists/{id}

```bash
curl -i -X DELETE http://localhost:8080/wishlists/7
```

Returns `204 No Content` with an empty body and deletes the wishlist's items with it. Deleting an id that does not exist also returns `204`, so the call is idempotent.

### Items

An item belongs to one wishlist. `product_id` must be an integer; `note` is an optional string of at most 255 characters, or null. The service stores the product ID but does not check a separate product catalog. `purchased` is a boolean that starts as `false`. Body fields `id`, `wishlist_id` and `purchased` are ignored on create and update; `purchased` only changes through the purchase action.

Use the wishlist ID returned by `POST /wishlists`, then add an item:

```bash
WISHLIST_ID=7  # Replace with the ID returned by your request
curl -i -X POST http://localhost:8080/wishlists/$WISHLIST_ID/items \
  -H 'Content-Type: application/json' \
  -d '{"product_id": 456, "note": "red one"}'
```

This returns `201` with the saved item and its URL in `Location`. Use the returned item ID for the following requests:

```bash
ITEM_ID=1  # Replace with the new item ID
curl -i http://localhost:8080/wishlists/$WISHLIST_ID/items/$ITEM_ID
curl -i http://localhost:8080/wishlists/$WISHLIST_ID/items

curl -i -X PUT http://localhost:8080/wishlists/$WISHLIST_ID/items/$ITEM_ID \
  -H 'Content-Type: application/json' \
  -d '{"product_id": 456, "note": "blue one instead"}'

curl -i -X DELETE http://localhost:8080/wishlists/$WISHLIST_ID/items/$ITEM_ID
```

Read and update return the item JSON. List returns an array, or `[]` for an empty wishlist. `PUT` requires `product_id`; omitting `note` clears it. Deleting an item leaves its wishlist and the other items unchanged.

- `400`: invalid JSON or missing/invalid item fields on create or update, including a `note` longer than 255 characters.
- `415`: create or update request without `Content-Type: application/json`.
- `404`: parent wishlist does not exist, the item belongs to another wishlist, or a read/update requests a missing item.

Deleting a missing or already deleted item returns `204` with no body, as long as the parent wishlist exists. Deleting an item that belongs to another wishlist still returns `404` and leaves it unchanged.

### Errors

Every error is returned as JSON in this format, never as HTML:

```json
{"error": "Not Found", "message": "Wishlist with id '7' was not found.", "status": 404}
```

`405 Method Not Allowed` responses include an `Allow` header listing the supported methods. `500 Internal Server Error` responses return a generic message; details are only written to the log.
